# 清理范围与执行清单

XStats 在扫描后生成本次清理清单，展示候选、大小和跳过原因。确认后仅处理选中的候选或工具操作；清理前重新检查保留项、应用运行状态和路径安全。

清理功能默认开启，已保存的关闭设置会保留。可从侧栏“优化清理”或磁盘页右上角“清理空间”进入；入口仅在清理功能开启时显示，与磁盘监控开关独立。默认开启不会在后台自动扫描，进入清理页后才按需扫描，执行清理仍需确认。

目录清理支持逐项选择，文件合计按已计量对象去重。包管理器缓存由原生工具整体处理，各工具容量单独展示，不计入文件合计，避免重叠范围重复相加。占用估计不保证实际释放量。“保留项目”列表仅存储在本机，最多 50 条；包含保留项的父候选也不会被删除。

“优化清理”分为“清理”和“优化”两个 Tab。清理 Tab 保留空间扫描、逐项审阅和清理确认；29 条静态缓存预览规则仅展示“已确认的缓存目录；占用不代表可安全删除。”，不提供清理选择，其占用与可清理容量分开显示。优化 Tab 提供手动刷新 DNS 缓存、释放内存，以及只读的 Homebrew 依赖预览；维护操作沿用已有辅助工具或管理员授权流程，依赖预览不执行移除。

切换到优化 Tab 会停止正在进行的清理扫描；打开优化 Tab 不自动运行维护或预览。离开优化清理页面、切回清理、隐藏主窗口、锁屏或休眠会取消依赖预览，恢复后不会自动重跑。原系统检查卡片及四范围选择器已移除；配置、资源、网络和存储审阅实现保留在内部，当前不提供界面入口。固定路径与 Mole 的逐项差异见 [优化清理与 Mole 对照](MAINTENANCE_PREVIEW.md)。

## 审阅与选择

清理页面沿用双列分类卡片，顶部空间摘要中显示所选项目数量和清理入口；废纸篓偏好、保留项目与清理日志固定在窗口底部；确定没有可清理内容的规则收在“无需清理”中，运行中、权限不足、扫描失败和跳过状态直接展示。复选框区分未选、部分选中和全选，点击部分选中会补齐该规则的选择。工具托管缓存仍整条执行，不支持逐项清理。确认框根据所选项目的实际删除方式生成：仅选废纸篓时明确提示永久删除且无法撤销；混合选择分别列出永久删除和移到废纸篓的数量与大小。

项目产物在独立窗口按项目分组，可搜索路径、筛选产物类型及按名称或大小排序。项目组勾选只作用于当前筛选下的可见产物，隐藏选择仍计入底部总数，可用“清除选择”统一取消；默认不选择任何产物。时间说明依据文件修改时间，不代表项目最后使用时间。确认前继续提示近期修改和云盘同步风险。

## 应用专属缓存

系统分类补充以下应用的缓存，默认不勾选，沿用逐项审阅、保留项目和清理确认流程。除 Codex 外，路径均相对 `~/Library/Application Support/`。通用“应用缓存”继续处理 `~/Library/Caches`，但始终让出专属目录和指向专属目录的符号链接别名，即使专属规则被运行状态拦截或未被选中，也不会接管其目录。

| 应用 | 缓存子目录 | 保留范围 |
|---|---|---|
| Slack | `Slack/Cache` | 账号、设置、本地存储与 Service Worker 数据 |
| Discord | `discord/Cache` | 账号、设置、本地存储与 Service Worker 数据 |
| Microsoft Teams（旧版） | `Microsoft/Teams/Cache`、`Code Cache`、`GPUCache` | 账号、设置、数据库、日志与临时文件 |
| Claude、Antigravity | 对应目录中的 `Cache`、`Code Cache`、`GPUCache`、`DawnGraphiteCache`、`DawnWebGPUCache` | 会话、账号、设置、本地存储和模型 |
| Qoder、CodeBuddy（含 CN） | 对应目录中的上述五类缓存，以及 `CachedData`、`CachedExtensionVSIXs` | 已安装扩展、工作区、账号、会话与共享插件数据 |
| Codex | `~/Library/Caches/Codex` 下 `Default`、`Default/Partitions/codex-browser-app`、`codex-browser-app` 中的 `Cache` 与 `Code Cache` | 各配置的 Local Storage、IndexedDB、Cookies 等用户状态；不清理整个缓存根或 Sparkle 更新目录 |

通过 bundle ID（含辅助进程）、可执行文件名和原生应用名称识别运行状态；Qoder（`com.qoder.ide`）与国际版 CodeBuddy 的标识来自第三方资料、尚未在真机核实，名称与可执行文件名保护继续兜底。应用运行时跳过，每个候选执行前再次检查运行状态、保留项目、最近修改时间与路径安全（最近修改除目录自身外，还会有界检查最多 3 层、2000 个条目内的最近写入）；确认框冻结弹出时的选择，并提示正在运行的应用对应项目会被跳过、实际数量可能少于所示；家目录以下任意父目录或缓存目录为符号链接时拒绝清理。只识别上述明确目录，不清空整个 Application Support，不扩展到新版 Teams 的容器数据。不存在的缓存不会作为待清理项目显示。清理方式遵循现有“优先移到废纸篓”偏好，关闭该偏好时直接删除。

## 只读缓存与维护审阅

`PreviewRuleCatalog` 的 29 条静态规则与上述可执行的应用专属缓存规则分开管理：新增范围包括有限的应用、浏览器、云盘与 Office、开发工具、虚拟化缓存，以及明确的 Application Support 缓存叶子、QuickLook 和图标缓存。目录名称和大小写均有固定 Mole 源证据，不扫描整个应用容器、同步目录或 Application Support。规则全部 `previewOnly`，复用现有缓存工厂与运行保护；没有触发保护也不代表对象闲置，尤其不能据应用名称完整识别 CLI 活动。

通用缓存与日志扫描须让出预览保留范围，执行时同样复核，不能经由父候选或旧计划删除。预览规则不能勾选，执行引擎也拒绝清理；没有新增删除根或通用容器白名单。

内部保留的配置审阅（当前无界面入口）中，Saved State 独立于缓存规则，只枚举用户保存状态目录的直接 `.savedState` 子目录，按目录 mtime 超过 30 天筛选，跳过运行应用和符号链接候选，完整计量后才展示占用。它不表示应用 30 天未使用，也不提供清理选择。

内部保留的存储审阅（当前无界面入口）仅在声明的数据库和目录内有界读取：数据库空闲页不是可回收空间，模型、设备备份和虚拟磁盘是用户数据；有限应用清单未匹配不代表卸载或孤儿，旧式备份标记不代表备份失败。缺少权限、工具、完整计量或状态证据时显示未知或部分完成，不自动转成可清理候选。

## 与 Mole 的范围差异

早期应用缓存以 Mole V1.61.0 为参考；新的 dry-run 对照固定到 Mole `2ef9747535725d6370d4aebb4a3a58ecd1521488`。XStats 独立实现原生规则，不要求安装 Mole，不执行其脚本或解析终端输出生成删除授权。

| Mole 入口 | XStats 有限覆盖 | 未对齐的边界 |
|---|---|---|
| `mo clean --dry-run` | 复用现有清理规则，补充 29 条只读静态缓存规则 | 不覆盖所有产品、Profile、容器、数据根及系统级操作；占用不等于垃圾或可释放容量 |
| `mo purge --dry-run` | 复用独立项目产物窗口及 Git、保留项目与确认保护 | 不承诺产物类型、搜索根、忽略规则与 Mole 完全一致 |
| `mo optimize --dry-run` | 优化 Tab 提供 Homebrew 依赖预览；另保留 DNS 刷新与内存释放的既有手动操作 | 不批量执行设置写入、数据库维护、索引重建、网络重置或自动修复 |

15 类清理范围、19 个 optimize 操作及每项延期边界均见 [优化清理与 Mole 对照](MAINTENANCE_PREVIEW.md)。未覆盖项不会因本机 dry-run 未出现而被视为不存在；两个工具的候选数量或总容量无需一致。后续对照也不意味着照搬上游全部删除行为。

## 开发者清理清单

开发者分类按本次扫描得到的可清理总容量从大到小展示；容量相同或暂不可清理的规则保持清单顺序。

| 项目 | 扫描范围 | 执行方式与限制 |
|---|---|---|
| Xcode 编译缓存 | `~/Library/Developer/Xcode/DerivedData` 下的候选 | 按选中目录清理；Xcode 运行时跳过 |
| 模拟器缓存 | `~/Library/Developer/CoreSimulator/Caches` 下的候选 | 按选中目录清理；模拟器运行时跳过 |
| npm | 查询实际 cache 下的 `_cacache` | 固定 `--cache` 后执行 `npm cache clean --force` |
| Yarn Classic | 查询缓存目录并确认配置根 | 固定 `--cache-folder`；原生命令删除整个配置根，包含版本目录的兄弟项 |
| Yarn Berry | 查询 `cacheFolder` 与 `globalFolder` 的缓存位置 | 固定配置位置后执行 `cache clean --all`；插件可能有额外全局操作，有保留项时暂停 |
| pnpm | `pnpm store path` 返回的当前版本存储 | `--store-dir` 使用经过验证的配置父目录，预览只计量版本目录；执行 `store prune` |
| Bun | `bun pm cache` 返回的实际缓存 | 用 `BUN_INSTALL_CACHE_DIR` 固定范围；隔离临时工作目录，执行结束后释放 |
| Go | `go env -json GOCACHE GOMODCACHE` | 编译与模块缓存使用同一份规范化路径预览和执行；`GOCACHE=off` 单独处理 |
| Rust | `CARGO_HOME` 下的 `registry` 和 `git` | 固定 `CARGO_HOME` 后执行 `cargo-cache -r all`；不清理已安装的二进制工具 |
| uv | `uv cache dir` 返回的实际缓存 | 固定 `--cache-dir` 后执行 `uv cache clean` |
| pip | `pip3 cache dir` 返回的实际缓存 | 固定 `--cache-dir` 后执行 `pip3 cache purge`；不清理虚拟环境和已安装的包；缓存格式支持取决于本机 pip3 版本 |
| Homebrew | `brew cleanup --prune=30 --dry-run` 的原生预览 | 清理旧版本与缓存，不自动移除依赖；仅空目录、断链等 0 字节维护项显示“无需清理”；全局操作无法锁定完整路径，有保留项时暂停 |
| VS Code | Code、Code - Insiders 下的 `Cache`、`Code Cache`、`GPUCache`、`CachedData`、`CachedExtensionVSIXs` | 应用退出后按目录清理；保留设置、扩展、工作区状态与会话 |
| Cursor | Cursor 下的 `Cache`、`Code Cache`、`GPUCache`、`CachedExtensionVSIXs` | 应用退出后按目录清理；保留设置、扩展、工作区状态与会话 |
| Xcode 归档 | `~/Library/Developer/Xcode/Archives` 下的候选 | 默认不选，确认后移到废纸篓；删除归档会影响旧版本崩溃符号化 |

新增的 pip、VS Code 和 Cursor 项目默认不勾选。只识别已有工具和明确目录，不自动安装或更新开发工具。工具查询失败、路径无法确认或扫描不完整时，不执行整项原生清理。

未新增 Gradle、Maven、Docker 资源、AI 模型或历史会话的删除操作。存储审阅可计量部分固定 Docker、VM 和模型目录，但不处理构建锁、本地制品或运行状态，也不把它们作为普通下载缓存清理；其他位置继续使用对应专项或空间分析。

## Agent 数据

“Agent 数据”为默认关闭的实验性功能，可在“设置 → 功能 → 实验性功能”中启用。启用后，优化清理页右上角显示“Agent 数据”入口，与“项目产物”并列；清理功能也需开启。“Agent 数据”按需盘点 AI 工具的本地数据与 worktree，覆盖 Codex、Claude Code、Gemini CLI、OpenCode、Cursor Agent、Aider、VS Code（Copilot）、Grok Build、Claude Desktop、DeepSeek Harness、Pi、Cindy、CodeBuddy 和腾讯 WorkBuddy（国内版与国际版／Workbuddy-AI 合并识别）。检测到对应命令或标准应用目录中具有匹配 bundle ID 与可执行文件的桌面应用，才计为已安装；Codex 桌面应用与 CLI 合并计一种，Claude Desktop 与 Claude Code 分开列出。只列出已安装工具及其已存在的关联数据目录；仅有残留数据目录不视为已安装，也不展示或计量。

VS Code 仅计量默认 Code／Code - Insiders 用户目录中 `globalStorage/github.copilot-chat` 与 `globalStorage/emptyWindowChatSessions`，不把整个编辑器、扩展、共享工作区存储或项目算作 Agent 数据；此范围不代表全部 VS Code Agent 数据。Cindy 的中国与全球版数据合并盘点，但不重复统计外部 Codex、Claude 或 Pi 目录。工具占用仅排除由 Worktree 页另行发现的 Codex、Claude 根目录下的托管 worktree，不读取会话或凭据内容。支持 `CODEX_HOME`、`CLAUDE_CONFIG_DIR`、`GROK_HOME`、`DSH_HOME`、`PI_CODING_AGENT_DIR` 与 OpenCode 的 XDG 数据目录；默认与自定义位置均仅作只读盘点。跨工具路径重叠时不重复计量，并标为未完整统计。

AI 工具页仅显示已安装工具、数据目录及占用，并支持在 Finder 中打开目录。不提供日志或工具数据的清理、删除操作，也不生成清理候选或开放专用删除白名单；不会修改日志、会话、凭据、配置、SQLite、快照、模型或工具本体。

worktree 仅由 Git 的登记清单确认，排除主工作目录并按路径去重。默认覆盖工具托管位置和家目录内常见项目位置，允许本次添加扫描目录，不进行全盘搜索。项目发现深度不超过 4 层、目录条目不超过 5,000、仓库不超过 80 个、worktree 不超过 200 个；工具统计与 worktree 发现共用 25 秒截止时间；桌面应用识别与工具统计合计最多占用前 10 秒，其中应用识别仅枚举标准应用目录的直接子项，上限为 1,000 条／2 秒；工具与 worktree 阶段分别保留 60,000 条目预算，单个工具目录上限为 30,000 条／2 秒，避免新增工具耗尽 worktree 的扫描预算。无法完成的占用显示未完整统计。扫描范围可在页面查看，检测数量不代表整台 Mac 的总量。

移除必须逐项确认，在确认前和执行前检查目录身份、Git 公共目录、登记位置、HEAD 和分支是否仍一致。现有保留项目、修改、未跟踪及被忽略的文件、锁定、子模块、未由引用保留的独立提交或检查失败都会阻止移除。仅允许家目录内、无符号链接的真实工作目录。执行普通 `git worktree remove`，不强制删除、不删分支、不清理失效登记；Git 命令关闭钩子与文件监视器，限制运行时间和输出。移除目录不经过废纸篓，确认框提醒先结束 Agent 会话和编辑器；文件检查无法识别未保存的编辑器缓冲区。

首次打开时扫描，最近一次完成的结果仅缓存在当前应用进程内。再次打开、恢复窗口、解锁或唤醒时复用结果，不后台轮询；安装或卸载工具、外部修改目录后可点“重新扫描”。添加扫描目录、移除 Worktree 后重新扫描；保留项目变化会使旧结果失效，移除前仍重新进行安全检查。重启应用后首次打开重新扫描。

关闭页面、关闭/最小化主窗口、关闭清理功能或 Agent 数据实验开关、锁屏或休眠时取消任务；过期任务不会更新界面，未完成且没有缓存的扫描在恢复页面时重试。超时和取消不被当作成功。

## 执行边界

- 每条开发者规则由 `DeveloperCleanupCatalog` 定义，原生规则只生成一份 `ToolCachePlan`。确认后的执行复用这份计划，不回退到默认路径或另一套命令。
- 支持限制缓存位置的工具通过参数或环境变量锁定目录。Homebrew 和 Yarn Berry 属于全局工具操作，预览不等于不可变的逐文件删除清单。
- 工具缓存从通用缓存和日志候选中去重，避免重复计量或绕过工具直接删除。
- 扫描最多并发两条规则；只读工具查询有超时和输出大小限制。关闭或取消后不维持额外轮询。
- 卸载扫描会分别保留已验证的候选与读取失败的位置。确认窗口会提示可能仍有残留；应用本体不可读或扫描被取消时停止操作。

## 卸载残留保护

卸载扫描和确认后的后台检查会检查 `/Applications`、`~/Applications` 及一层子目录。存在相同标识的其他副本，或安装位置无法完整读取时，仅移除所选应用本体，保留共用数据。副本检查不覆盖磁盘上的任意其他位置。

路径保护逐级检查真实符号链接，允许 APFS 的大小写规范化。残留识别补充登录项组件、完整名称变体、可执行文件名对应的崩溃报告、WebKit 与 NSURLSession 的应用子缓存，以及系统返回的当前用户缓存目录中的标识子项。名称匹配、OpenCode 与命令行可能共用的目录默认不选；共享父目录保留。

部分回收失败后保留原扫描的候选和组件身份，仅对原清单中的剩余项重试；执行前重新检查路径与其他安装副本。副本检查和目录遍历在现有后台任务中进行，功能关闭后不继续提交新的回收操作。
