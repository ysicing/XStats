# 开发交接

- 清理状态须区分工具超时和读取失败，不能用统一警告全部归因于权限；失败不能显示成空缓存，清理能力标记也不能与运行或空结果混写。
- 应用缓存列表不能用卸载列表的“未匹配”直接推断已卸载：卸载列表会跳过链接应用及不可读目录。缓存页须保留读取完整性，识别链接安装；只隐藏完整空结果，运行保护、权限失败和扫描中断不代表无缓存。历史仅记录本机确认见过的应用，单有缓存只能标“缓存残留”，行隐藏也不能撤销专属目录保护。应用清单读取失败或不完整时只能标为未知，不能凭历史记录显示“曾安装”。
- 清理目录不设条目、候选数量及固定时限，不做额度分配与补扫；外部工具预览仍独立计时，不能把工具耗时算进后续目录计量。`ScanBudget` 默认有界供配置、存储等检查使用，只有清理入口关闭数量与时间限制，取消检查始终有效。取消检查须覆盖候选排序、硬链接整理与跨规则去重，不能只放在目录遍历中；无数量上限后，大候选数组的排序可拖延取消数秒，路径与深度应预先计算。取消整理时不得返回尚未完成范围保护的清单。首轮从两个名额开始，按需复用新鲜 CPU 样本及当前内存／温度状态决定并发，上限取可用逻辑处理器数的一半（至少两个），不增加常驻监控。降档只停止补位；严重压力下派发暂停，组内任务耗尽也不能丢弃队列，等待须可取消。调度回归固定处理器数、负载与单调时钟，不依赖开发机状态。规则未完整计量的目录不得发布容量或进入清理。
- 本机限并发构建时，`xcodebuild -jobs` 不能约束 Release Swift Package 的 WMO 后端线程；`SWIFT_NUM_THREADS` 和较早传入的 `-num-threads` 可能被生成参数覆盖。临时 xcconfig 设置 `SWIFT_USE_PARALLEL_WHOLE_MODULE_OPTIMIZATION = NO` 并配合 `OTHER_SWIFT_FLAGS = $(inherited) -j2`，再从实际编译命令核对 `-num-threads 1`；不要为本地预览修改项目全局构建配置。
- 工具检查需要完整输出时须显式启用字节上限并在超限时整体失败，不能解析普通命令保留的尾部。回归须经过 `CleanEnvironment.inspectTool` 生产入口；单测底层 runner 不能证明接线正确。
- 逐层 `O_NOFOLLOW` 存储检查的夹具必须使用 `realpath` 后的物理临时根；Foundation URL 规范化可能仍保留 `/var` 别名，不应为了夹具放宽生产链接保护。
- 有界目录发现先计遍历条目，业务筛选后才计审阅候选；无关偏好文件不能消耗所有候选名额，导致共享预算下的后续数据库和存储检查永远无法完成。
- 只读清理规则须同时限制选择和执行，并让通用 Caches / Logs 规则在扫描及旧清单执行时让出预览目录；仅在扫描后去重无法保护被跳过的预览项。工具范围因预算或预览失败而未知时，通用规则也不能接管该范围，阻止状态须随逐项选择保留。有保留项时，Homebrew、Yarn Berry 等无界全局操作不能在 `prepareTool` 中提前抛错：丢失计划会被视为范围未知，连带阻断所有通用缓存与日志。须照常运行只读预览，由引擎拒绝执行并保留计划根路径供通用规则让出。
- 清理占用按选中对象求并集：硬链接跨候选、跨规则仍只累计一次，但单个候选保留自身完整大小。工具通常整体清理，无法可靠排除与其他工具的重叠；工具估算独立展示，不加入文件容量合计，也不能为去重而裁剪其执行计划。
- 端口页的通配地址显示为 `*`，但冲突判断必须保留内核 `insi_vflag` 的 IPv4、IPv6 或双栈信息；不同本地地址不能只因端口号相同就标记冲突，标记结果须关联具体 socket。
- 进程页的“查看应用”须限制在应用清单支持的 `/Applications`、`~/Applications` 及一层子目录，不为跳转扩大扫描范围；其他位置沿用访达入口。导航目标被搜索或范围筛选隐藏时，不能误报目标已退出，须依据完整采样结果判断。
- `brew services list` 属于只读预览，`services start/stop/restart` 属于写操作；不要让服务启停进入预览超时后终止进程的路径。回归使用隔离的假 `brew`，避免修改开发机服务。
- Homebrew 包与服务分属两个控制器，各自的忙碌状态不能阻止跨页并发；写操作必须共用 `HomebrewOperationState`，在启动任务前同步获取，切页不释放。写操作超时仅停止等待结果，须通过退出通知等待实际进程结束，再清除忙碌状态并释放共享写锁。
- 退出确认须同时检查包操作和服务操作，不能直接用共享写锁代替，否则会改变索引更新的退出语义。退出提示只能说明已启动的命令可能继续运行，不能承诺预检查中的启停操作会在后台完成。服务写操作超时只代表停止等待，brew 可能仍在运行；应提示在终端核对，不能按确定失败建议重试。启停前的清单预检查超时须在服务层单独转换：读取进程会被停止，启停尚未执行，可以刷新后重试；回归须经过服务层的两阶段调用，不能只向 UI 注入同一种超时错误。
- 网络页被端口 sheet 遮挡时应暂停其详情需求，否则两个控制器会分别调用 `nettop`；保留独立网络菜单栏弹窗的可见需求，关闭 sheet 后恢复网络页。
- Capture 的异步置顶请求等待图片处理期间，录制可能先禁用再恢复置顶；仅检查当前 `canPin` 会复活旧请求，须核对提交时的代际。回归应控制待处理工作并等待实际请求完成，不能依赖固定次数的 `Task.yield()`。
- `CaptureCallback` 的注册中取消回归在同步注册回调内取消当前任务，直接核对注册返回后才清理的顺序；不要在 `Task.detached` 中用信号量等待另一协作任务释放，它仍使用协作线程池，单工作线程下会等到超时并产生连锁断言失败。
- Helper 的睡眠与风扇恢复标记必须独立保留；启动恢复先接回完整状态，每项只在实际恢复成功后清除。SMC 手动写入可能部分生效，必须先成功持久化恢复意图，落盘失败禁止新接管，但不能阻止尽力恢复。`Ftst` 已知存在却读不到时须尝试复位，失败保留恢复标记。旧版本没有具体风扇编号的标记，不能因恢复一个风扇而清除。
- 睡眠、锁屏先暂停普通监控、历史与界面更新，风扇复位须等待在途写入；尚未成功交还系统时，仅按原间隔保留 CPU 温度保护，复位成功即停止此读取方。恢复会清除复位成功标记，在途复位未结束时再次暂停复用原任务，不能沿用上轮复位成功状态。防休眠的 Helper 写入也须串行收敛到最新需求，取消调用方不能撤销已经生效的系统写入。
- 合盖运行的低电量保护不能随锁屏或息屏停止；暂停期间复用采样循环，每 30 秒只读电池，保护专用快照不发布普通监控状态、不写历史。风扇保护仅使用仍有需求时新采到的温度，纯电量快照不能回退旧温度、改掉已保留的风扇档位。风扇独立需求也须能按既有采样重试首次失败的 SMC 连接，温度发现和风扇读取共用 30 秒重连预算。
- `AppModel` 初始化会通过 `MetricsStore` 读取一次本机电池；验证安全采样不更新普通监控状态时，应比较处理前后的电池状态，不要假定初始值为空，否则测试会受开发机或 CI 是否有电池影响。
- 音频输出切换取消时，只要功能仍启用且未休眠，就要先恢复当前设备上的静音、音量与路由，再释放过渡保护；关闭和休眠不得恢复旧管线，旧请求也不得移除新请求的保护。再次切换须先让新保护接管旧保护覆盖的全部进程，不能只收集已恢复的管线；二次准备失败也须保护仍未恢复的应用，不能释放新旧保护后遗留静音管线。
- 连续音频切换还须继承尚未恢复的处理名额，新应用不能抢占；需求撤销或应用退出才释放，并同步移除该应用的过渡静音，不等待其他应用恢复。关闭功能时取消在途音量任务，已进入 HAL 的写入可能完成，但其后的取消静音必须检查取消状态。切换设备、静音等普通操作只丢弃排队音量，并等待在途写入及其取消静音完成，否则切换会让后续取消静音因路由变化失败；等待后还须复核任务取消、操作代际和功能生命周期。
- 应用音量的私有 aggregate 就绪后，须显式设置为目标输出的名义采样率，并有界、可取消地等待实际 tap 输入流同步后再校验；HAL setter 返回成功不代表格式已生效，指定主子设备也不保证 tap 自动同步。Aunbox 的 8 kHz 输出曾与默认 48 kHz tap 不一致，被误判为格式不支持；由 HAL 转换，不放宽等采样率及缓冲区布局校验。硬件回归仅显式设置 `XSTATS_AUDIO_TEST_OUTPUT_UID` 时启用，所选设备须与原生 tap 采样率不同，并额外验证默认输出，不切换默认设备或调整用户音量。
- 卸载预览须绑定应用目录的文件身份和 Bundle ID，执行前重新核对；同路径替换应用必须重新扫描。本体已移走时可重试原残留。Bundle ID 前缀不能证明归属，独立安装的派生 ID 数据须保护，未知派生残留默认待确认。候选先展示、大小后统计时须显式标记未知大小，回填不重置勾选，晚到的计量结果仍检查扫描代际；取消后的部分结果不能作为卸载授权。
- `LaunchItem` 公开初始化器只构造展示数据，不读取文件；启停须使用扫描得到的配置快照，无快照时在执行 `launchctl` 前拒绝。启停 LaunchAgent 前重新核对预览时的完整 plist 配置及值类型；Foundation 字典相等会将布尔与整数、整数与实数视为相等，不能直接用于配置复核。启用时 bootstrap 直接使用原 plist 路径，不使用临时快照：快照随后被删除会让 launchd 登记指向已消失的路径，而能写入 LaunchAgents 目录者本就拥有当前用户权限。复核与 bootstrap 之间仍可被替换，该残余 TOCTOU 已接受。
- 主应用的 ad-hoc／未签名构建可通过 Sparkle 升级正式版，不能因当前构建缺少 Team ID 拦截安装；仍限制主产品 Bundle ID，保留签名清单、内置公钥验证及正式发布的签名、公证门禁。Helper 与网络组件的团队签名要求独立保留。
- Capture 保存期间须同时拦截原生 `NSView.keyDown`，SwiftUI 的 `.disabled` 不能阻止第一响应者接收快捷键。回归使用真实窗口事件与受控保存接口。
- Magpie 刷新完成和失败都要触发 Widget 同步；额度窗口按当前时刻筛选，当天零点只用于日期键和今日用量。测试通知使用独立标识并仅受系统授权约束，不依赖业务告警开关。
- 出口检测关闭窗口或暂停时须取消测量任务；环境读取、测量、归属地查询和发布边界都核对取消与代际，晚到的进度和结果不能更新界面或偏好。底层批量请求取消后不再调度后续任务或 DNS 备用请求。
- 历史暂停刷盘保留当前分钟的累计样本与峰值；写库顺序须与采样、清空顺序一致。正常退出统一走异步准备，先停止新增采样，再等待当前分钟及此前所有写入完成，不能只在 `applicationWillTerminate` 启动任务。退出不等待无期限 XPC，冻结控制意图后由 `applicationWillTerminate` 中原有的 1.5 秒同步预算恢复系统，避免 Helper 无响应连带阻塞刷盘与退出。
- `launchctl` 的通用 I/O 错误不能直接视作已加载；先确认 enable/disable 成功，bootstrap/bootout 非零时须验证用户域中目标的实际状态。HTTP 长度与分块大小须在切片前校验符号、格式、溢出及剩余字节数；分块扩展前的 BWS 合法，收紧格式时不能连同拒绝。零长度末块后还须读完 trailer-section 的终止空行，支持合法 trailer，不能把连接关闭或截断 trailer 当作完整响应。
- 发布版本对象的存在性预检不能保证不可变，最终上传也必须使用服务端条件创建；同内容并发冲突可回读哈希继续，不同内容、权限及网络错误必须停止发布。离线回归在预检后注入竞争对象，禁止触碰真实源站。
- 发布清单生成与 ZIP 校验均须核对根应用的 Bundle ID、版本和构建号，发布入口还须将清单构建号绑定到当前工程声明；源码来源证明及扩展版本匹配不能代替根应用版本校验。测试夹具必须写入真实结构的 `Contents/Info.plist`，不为旧夹具放宽生产检查。
- Widget 共享摘要缺失、损坏或无权读取时不能推断功能关闭；临时签名可能被系统拒绝访问 App Group，本地小组件验收须使用有授权的团队签名。检查 `containermanagerd` 与 `cfprefsd` 的实际拒绝记录，不能以 UserDefaults 对象非空或 `set` 返回确认跨进程共享成功。
- 原生图标颜色回归使用固定 `.deviceRGB` 的 `NSBitmapImageRep`，在同一明确外观中绘图和解析系统色；`NSImage.tiffRepresentation` 可能携带显示器 HDR 映射，回读像素会偏色，不能通过放宽颜色容差规避。
- 发布时复用未超过 7 天的线上地图库，只读取清单并用 HEAD 核对文件存在和大小；重复完整下载曾因 CDN 节点连接重置拖延应用发版。实际更新地图库仍须完整回读并校验 SHA-256 后才更新清单，不能用 HEAD 代替上传验收。
