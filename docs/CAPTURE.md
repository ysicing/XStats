# XStats Capture

XStats Capture 支持 macOS 14+ 和 Apple Silicon，由共享的 `CaptureCore`、`CaptureUI` 组件提供两种宿主：XStats 内置工具和独立 macOS App。XStats 使用按需启用的内置 Capture，无须安装独立 App；独立版可以脱离 XStats 使用，不加载系统监控、网络扩展或辅助工具。独立版为 0.1.5（6），通过 [Capture Release](https://github.com/ysicing/XStats/releases/tag/capture-v0.1.5) 下载已签名、公证的 DMG，或运行 `brew install --cask ysicing/tap/xstats-capture` 安装。应用菜单提供“关于”“检查更新…”和“自动检查更新”；Sparkle 管理检查、跳过版本及用户确认后的安装，不自动下载或安装。更新检查向区域 API 发送 Capture 版本和安装标识的哈希，不发送截图、录屏或系统分析。

## 本地构建与启动

```bash
task compile-capture                # 验证构建，不安装、不修改版本
task run-capture                    # 构建并打开独立 App
task compile                        # 验证 XStats 集成，不安装、不修改版本
task test                           # 全仓库脚本、Go 和 Swift 测试
```

产物位于 `build/DerivedData-capture-arm64/Build/Products/Release/XStats Capture.app`。可以将它复制到应用程序文件夹，也可以从构建目录打开。麦克风需要有效签名和 `com.apple.security.device.audio-input` entitlement；无 Developer ID 时，Capture 编译任务使用本地 ad-hoc 签名。测试脚本需要 Python 3.10+。

XStats 的“设置 → 功能 → 可选功能 → XStats Capture”默认关闭，启用后显示内置截图、录屏入口和快捷键设置；关闭后隐藏这些入口、解除全局快捷键并保留配置，已打开的编辑与录制任务可继续处理。内置功能直接在 XStats 进程中运行。设置页出现、XStats 重新激活及显式打开时，通过系统登记查询并验证独立 App，不扫描目录、不下载或轮询。发现独立版只显示切换入口，不改变当前选择；用户点击“改用独立版”且应用启动成功后，关闭内置功能并解除其快捷键。内置 Capture 窗口或任务尚未关闭时提示先完成处理，不自动丢弃。启动失败恢复原状态；独立版被移除时保留选择并提示，可点击“改用内置版”手动启用。两个宿主的偏好和快捷键不自动迁移。内置版跟随 XStats 的语言与外观，不创建额外菜单栏入口；快捷键由 XStats 管理。独立版使用自己的偏好设置、语言、常驻状态和快捷键。

两种宿主的 Capture 主页都先切换“截图”或“录屏”，再选择区域、窗口或整个屏幕，点击对应的主按钮进入目标选择。录屏模式会显示声音选项；独立版右上角齿轮打开设置，可调整语言、常驻菜单栏及全局快捷键；内置版沿用 XStats 设置。

Capture 版本由 `project.yml` 中的 `CAPTURE_VERSION` 与 `CAPTURE_BUILD` 独立维护，主程序构建和发布不推进它们。两种 App 分别签名和授权：内置版的屏幕录制、系统声音与麦克风权限归属 XStats，独立版归属 XStats Capture，权限不共享。独立 target 不携带 XStats 的 Widget、监控组件或辅助工具，使用独立构建、版本、打包、公证和更新渠道。

## 独立发版与恢复

`task release-capture -- --publish` 从干净、已提交并推送的 `main` 构建和发布；本地验证先运行 `task test`、`task format`、`task format-check`。需要有效 Developer ID Application 证书、`XStats` 公证凭据、既有 Sparkle 密钥、对象存储和 `XSTATS_RELEASE_TOKEN`。版本来自 `CAPTURE_VERSION` / `CAPTURE_BUILD`，摘要来自 `docs/CaptureReleaseNotes.json` 的简体中文和英文；不修改 XStats 版本或安装本机应用。

产物写入 `dist/capture/`，来源记录绑定源码提交、摘要及全部制品哈希。应用和 DMG 均签名、公证、装订并验证 Gatekeeper；全部二进制为同团队签名的 arm64，UUID 匹配的 dSYM 私有备份后才继续。发布到独立 `capture/` 对象前缀，公开回读通过后依次发布 `xstats-capture` 的三区域 JSON、校验签名 XML、推送独立 Homebrew cask（推送前先同步 tap 最新提交），最后创建 `capture-v<版本>` Release 与标签（不替换 GitHub 最新主程序版本）。标签是“发布已完成”的唯一标志，因此中途失败不会留下让后续跟随检查误判为已发布的标签。主程序的版本、清单、Cask 和历史制品保持独立。

中断后保留原始制品和 `release-provenance.json`，确认源码未变，运行 `task release-capture -- --publish-only`（即 `python3 scripts/release_capture.py --publish-only`，幂等）续传；不重新构建或覆盖同名已公开制品。构建尚未完成时先核对日志与符号归档，不盲目重跑。

后续跟随 `task release-all`：发布前比较最近 `capture-v*` 标签与当前工作区（含已暂存、未暂存和未跟踪文件，不只是已提交的 HEAD），仅 Capture App、CaptureCore / CaptureUI、其翻译与共享更新代码、相关依赖和打包设置变化时要求发版。有相关改动须提前递增 Capture 的 semver 与构建号，并依据实际变化同步中英文摘要；主程序发布完成后自动执行独立发布。无关主程序、网络组件或文档变化会跳过 Capture，不推进其版本。`python3 scripts/release_capture.py --check-follow` 可提前检查；本地存在与 origin 指向不同提交的同名 `capture-v*` 标签时会报错并停止，不会自动覆盖，需核对后手动处理；若主程序已发布而 Capture 发布中断，独立恢复，不重发主程序。

## 截图

点击截图后，先选择区域、窗口或单个整个屏幕。选框会保留供确认：区域模式可拖动框内移动位置、拖动四角或边缘调整大小，工具栏显示像素尺寸；窗口与整个屏幕模式可重新选择目标。点击选中窗口后显示一次完整内容预览及窗口名称；过大或部分移出屏幕的窗口会等比缩小，以便确认完整内容，不改变目标应用的前后顺序。预览期间不会持续采集，重新选择或退出后释放预览。点击工具栏的截图按钮或按回车才执行截图，重新选择可清除当前范围，Esc 或取消按钮退出选择。区域限制在一个显示器内；切换到另一显示器选择时清除原来的选区。

截图会打开编辑窗口，支持裁剪、箭头、矩形、画笔、文字、马赛克及撤销/重做。先选工具，再在图片上拖动绘制；拖动时直接预览实际形状。文字工具在点击的位置打开输入框，按回车完成，Esc 取消。完成绘制后自动选中标注，可以拖动移动、拖动控制点调整大小或箭头端点；双击文字或选中后按回车可继续编辑。上方属性栏可修改颜色、粗细或字号，Delete 或“删除标注”移除选中的对象。移动、调整、修改和删除均支持撤销/重做，每次拖动只产生一步历史记录。

马赛克支持细、中、粗三档颗粒。选择马赛克工具或选中已有马赛克后，属性栏会显示“一键打码”。点击后，在本机使用 Vision 识别当前裁剪范围内的手机号、邮箱、中国大陆 18 位身份证号和银行卡号；身份证与银行卡会校验号码。国际电话号码需包含 `+` 国家区号，银行卡支持空格或短横线分组。准确识别失败时会尝试一次快速识别，并提示仔细检查；快速识别支持的语言可能更少，两者失败时显示错误。自动结果作为可移动、缩放、删除的马赛克标注加入，一次撤销可移除整批新增结果；再次识别会跳过已被单个马赛克完整覆盖的区域。识别期间可取消，关闭窗口也会取消任务；不上传图片或保存识别出的文字。识别可能遗漏或误判，分享前应检查并手动补充。

工具快捷键为 V 选择、C 裁剪、A 箭头、R 矩形、P 画笔、T 文字、X 马赛克；Esc 取消当前拖动或选择。Command-Z 撤销，Shift-Command-Z 重做，Command-C 复制，Command-S 默认保存 PNG。保存按钮旁的格式菜单可改用 JPEG。

复制与保存均输出合并后的图片。马赛克会写入最终像素；编辑过程保留原图和可撤销的标注，因此不要把原始截图当作已遮挡图片分享。默认保存 PNG，也可选 JPEG。置顶最多同时保留 5 张，关闭置顶窗口即可释放。

## 录屏

选择录屏模式与捕获范围，确认“系统声音”和“麦克风”，再点击对应的录制按钮。每次打开新录制入口时，默认开启系统声音、关闭麦克风；声音选择在开始前可见。选择目标后可按截图相同的方式调整与重新选择，点击“开始录屏”或按回车后才倒计时 3 秒，区域录制的坐标固定；窗口录制始终跟随选中的窗口，不会随当前活动窗口切换。倒计时和录制期间，区域或窗口外围持续显示可穿透点击的细边框，录制中为红色实线，暂停后为灰色虚线，不显示调整手柄。窗口边框随移动与缩放更新，控制窗口显示目标名称；目标最小化、隐藏或移出当前桌面时隐藏边框，并提示目标当前不可见，目标关闭后结束录制。停止或取消后移除边框。选区工具栏、范围边框与控制窗口排除在捕获内容之外；控制窗口优先放在捕获范围外，可暂停、继续和停止。控制窗口显示累计录制时长，从捕获成功开始计时，排除倒计时和暂停间隔；暂停时计时冻结，超过一小时显示时、分、秒。计时仅在控制窗口可见且录制运行时每秒刷新。暂停会停止屏幕与麦克风生产者，继续创建新片段；预览拼接时不保留暂停间隔。

录制为 SDR、30 fps，最长边不超过 3840 像素，不放大小画面。停止后可预览，通过同一条时间轴上的两个手柄调整首尾时间，再通过保存面板导出 MP4。左侧调整开始时间，右侧调整结束时间，选中部分高亮并显示保留时长；调整时暂停播放并定位到对应端点。手柄不能交叉，支持原生滑块的键盘调整与辅助功能。输出为 H.264 视频和混合后的单条 AAC 音轨；同时录制两路声音时各以 50% 音量混合，避免简单叠加削波。预览播放首尾范围可随裁剪设置变化。

系统声音遵循捕获范围：区域和整屏录制包含系统声音；窗口模式只包含所选窗口所属 App 的声音。麦克风独立于此范围。

实时编码短暂跟不上采集时，允许丢弃视频帧；音频在有界队列中保留并顺序写入。持续无法写入或队列超限时结束录制并报告错误。首次启动失败会清理本次临时素材，允许重新开始；暂停或继续失败时仍保留此前已完成的片段。

导出期间可以取消。导出失败或取消会保留原始片段和预览，允许重试；成功保存或确认丢弃后在后台清理临时素材。保存位置必须在整个录屏缓存目录之外，其他会话目录、子目录和指向这些目录的符号链接同样不可用，避免导出文件被随后清理。失败恢复入口也可在访达中显示原始片段。临时目录为用户缓存目录内的 `XStatsCapture/Recordings/<随机标识>`，没有永久媒体库。异常崩溃可能留下此处素材，可以在访达中恢复或手动删除。每次打开 Capture 时后台清理一次：未使用的会话最多保留 7 天，并按最旧优先限制为 20 个会话、10 GiB；最近 1 小时的素材暂时保留供恢复，正在使用的素材由跨进程文件锁保护，两种宿主不会互相清理活动录制。没有定时清理或永久媒体库，缓存目录不保证长期保留。

保存成功后的临时素材清理失败不改变导出结果；应用关闭预览并单独提示，可在访达中查看剩余素材。暂停、继续和停止失败时保留权限、捕获目标或媒体写入错误对应的恢复建议，不把系统捕获错误统一提示为磁盘空间不足。

流停止回调保留系统报告的原因，麦克风中断或设备断开提示检查设备，权限错误提示恢复权限。生产者停止失败时保留引用和控制窗口，允许再次点击停止；停止确认前不进入预览，暂停／继续入口暂时不可用。退出时仍执行生产者与素材清理。

## 权限与退出

只有发起捕获时才请求屏幕录制权限，只有启用麦克风录制时才请求麦克风权限。拒绝后在系统设置的“隐私与安全性”中恢复权限；应用不会静默关闭声音继续录制。恢复屏幕权限后，按系统提示重新启动 App。

独立版默认按需运行：所有窗口关闭且没有录制、导出或图片保存任务后退出。内置版在相同条件下释放 Capture 控制器、观察者及临时资源，XStats 继续运行；仅打开 Capture 不启用任何监控功能。退出 XStats 时，有 Capture 录制或未保存内容会提示，并等待捕获及图片任务收尾。存在未保存内容时提示处理。独立版可选常驻菜单栏，设置中可随时配置截图与录屏全局快捷键，常驻开启后生效。内置版在 XStats 的“设置 → 功能 → 可选功能 → XStats Capture”配置快捷键，仅在功能启用且 XStats 运行期间生效，关闭 Capture 窗口后仍可快捷唤起。两种宿主的快捷键配置分别保存，默认均未绑定，不需要辅助功能权限。快捷键注册不创建 Capture 工作区，也不启动采集或轮询。

点击快捷键按钮后按下组合键；Delete 清除，Esc 取消。编辑期间暂时解除本宿主的两项全局注册，避免原组合触发捕获；提交、取消、移开焦点或关闭设置后恢复注册。两个快捷键不能使用相同组合，也不能覆盖 macOS 默认截图快捷键。修改时遇到重复、无效或 Carbon 独占注册检测到占用的组合，会提示并保留原配置及有效注册；启动时遇到冲突则释放本次部分注册，修改配置后可重试。关闭独立版常驻或退出宿主会解除注册。两个 Capture 宿主使用独占注册，同一组合冲突时不会同时触发。部分第三方 App 使用非独占注册，系统可能允许共用组合，无法保证识别全部第三方占用。切换应用语言会更新所有已打开窗口的文字、标题、布局方向和菜单，保留截图编辑内容、置顶图片与录制预览状态。

确认丢弃并退出时，取消正在选择、启动、暂停或继续的任务，以及图片渲染和保存的后台任务，解除媒体写入后清理素材。退出会等待所有尚未收尾的图片任务完成临时文件清理，包括此前已取消的任务；等待期间不接受新的编辑或保存。图片保存先写入相邻临时文件，取消时不提交到目标文件；已经完成的保存不撤销。系统设备启动或停止的迟到回调只负责资源清理，不恢复录制或重新打开窗口；启动注册与取消按顺序协调，避免停止后又启动。

锁屏、休眠、区域／整屏录制的目标显示器断开、目标窗口关闭或媒体管线错误时结束录制，并尽可能完成已有片段。仅窗口录制期间，每秒核对所选窗口 ID 是否仍存在；停止后释放检查计时器。捕获遮罩与控制窗口不进入最终捕获。独立版排除自己的 App 窗口；内置版只排除 Capture 的主页、编辑器、预览、控制与置顶窗口，允许捕获 XStats 的其他窗口。录制开始前刷新排除列表，包含新建控制窗口及当时隐藏的 Capture 窗口。内置捕获、录制和导出任务期间禁用新建置顶，避免新窗口进入固定过滤范围；任务结束后恢复。窗口录制跟随选定窗口，窗口移动后无须重选，不因最初所在显示器断开而结束；显示器录制仅包含所选显示器。

## 开发边界

`CaptureCore` 负责目标、编辑模型、捕获、串行媒体写入和导出；`CaptureUI` 负责遮罩、编辑器、窗口生命周期与 Carbon 快捷键。它们只依赖系统框架和 `Localization`，不依赖整个 `XStatsUI` 或监控模块。XStats 通过按需创建的 `CaptureWorkspace(host: .embedded)` 使用共享组件；独立 App 的 delegate 使用 `.standalone` 宿主，并处理版本化 URL。CaptureWorkspace 不替换宿主 delegate 或应用菜单。内置控制器在空闲关窗后释放，重开时创建；独立宿主独占进程语言、常驻菜单栏和按需退出策略。两个宿主复用 CaptureShortcuts 与原生快捷键录入界面，各自管理 Carbon 注册和设置；内置快捷键生命周期独立于 Capture 控制器。

媒体写入只允许压力下丢弃视频帧。系统声音和麦克风分别保持有界的 PCM 待写队列，总量最多 64 个缓冲／4 MiB；仅有积压时重试，停止时逐轨排空再封口。连续 1 秒无法写入或超过容量时报告错误并结束采集，保留能成功封口的已有素材，不静默丢弃中途音频造成 AAC 时间线压缩。取消会解除待写任务，迟到回调不影响下一次录制。每条音轨按首个时间戳和实际输入采样率规范 PCM：极小的持续时钟偏差通过逐声道插值调整帧数，明显的时间间隙写入实际静音，重叠样本裁去重复帧，避免仅改时间戳被 AAC 编码器连续压缩。格式变化、非整数采样率、超过 1 秒的单次差值或超出内存边界会报告错误，不尝试无限补齐。线性插值仅用于至少 256 帧的缓冲，修正量不超过 1 帧或缓冲帧数的千分之一（取较大值），存在微小音质取舍；停止封口时按需记录数值统计，不记录媒体内容。

视频预览通过窄范围 `NSViewRepresentable` 使用原生 `AVPlayerView`，避免部分系统版本的 SwiftUI `VideoPlayer` 初始化崩溃；关闭或导出后解除播放器与素材引用。

支持的协议为 `xstats-capture://v1/open`、`xstats-capture://v1/screenshot`、`xstats-capture://v1/record`。未知版本、动作、转义路径或附加参数拒绝执行；忙碌时显示已有任务，不重复启动。外部录屏请求先展示范围和声音确认界面。

首版不含滚动截图、文字提取、云分享、GIF、自动缩放、视频遮挡、摄像头叠加或完整视频剪辑器。参考 [Apple ScreenCaptureKit 示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)与本机 SDK；[Vorssaint](https://github.com/vorssaint/vorssaint-utils#capture-and-create)仅作流程调研，未复制代码或素材。新增代码采用 AGPL-3.0-or-later。

### 缓存目录与手动清理

主应用与独立版共用 `~/Library/Caches/XStatsCapture/`，录屏会话固定存放在其 `Recordings/<UUID>/` 子目录；路径由 CaptureCore 的 `CaptureCache` 统一提供，不随宿主切换。截图及标注目前在内存中处理，不额外建立磁盘截图缓存。保存到用户所选位置的图片和视频不属于缓存，不参与清理。

独立版的设置、主应用的 XStats Capture 功能设置均提供缓存占用、可清理占用、在访达中显示和“清理录屏残留”入口。主应用的“快捷键、缓存与独立版”详情默认折叠，展开后才展示并统计缓存；折叠会取消当前统计。仅在展示缓存设置、手动刷新或重新激活应用时按需统计，没有后台轮询。手动清理须确认：它会移除不再使用的未保存录屏素材，但仍保留最近 1 小时的素材，并逐会话检查跨进程文件锁，保护正在录制、暂停、预览或导出的内容。自动清理沿用上述 7 天、20 个会话、10 GiB 的回收策略；通用应用缓存清理继续保护 XStats 目录，不能绕过此处的会话保护。

图片、视频导出的中间文件仍放在用户所选目标文件旁，以便在同一磁盘安全替换文件；正常结束、失败或取消会移除中间文件。进程崩溃可能留下隐藏的中间文件，这些不在录屏缓存清理范围内，也不会扫描用户目录并批量删除隐藏文件。
