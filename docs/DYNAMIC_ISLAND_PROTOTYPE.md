# 灵动岛窗口与设置

原生 AppKit / SwiftUI 顶部窗口接入 XStats 当前实例的真实系统指标、AI 额度、电池及休息计时。默认关闭；启用状态、场景和展示偏好随应用重启保留。

在 **设置 → 功能 → 可选功能 → 灵动岛** 启用，之后可以打开“设置”。显示内容可独立勾选系统、AI 用量、休息与电池场景，以及 CPU、内存、温度与功耗指标；至少保留一个场景和一项系统指标，仅有一个场景时隐藏切换栏。取消当前场景后自动切换到首个保留场景，默认场景仅可从保留的场景中选择。显示选项包含目标屏幕、默认场景、显示样式、展开尺寸、菜单栏间距和全屏隐藏；交互选项包含点击展开、悬停预览、悬停展开及对应延迟。窗口运行期间菜单栏出现独立的胶囊图标，可以展开、收起、切换显示器或关闭灵动岛。

也可以退出 XStats 后，使用正常主程序启动并启用灵动岛：

```sh
open /Applications/XStats.app --args --island
```

- 系统场景收起时显示首个已选指标，按 CPU、内存、温度、功耗的顺序确定；展开后显示其余已选指标。默认全部选中，与原有显示一致。复用 `MetricsStore` 与 `MetricsHub`，按当前展示内容合并采样需求，不创建独立采集器。展开时使用现有每秒实时采样，收起后只保留首个已选指标的展示需求，取消勾选立即移除对应的额外采样需求；其他窗口和历史所需的采样不受影响。
- 遵守基础监控和能耗开关，不为展示自动开启功能。关闭模块时保留场景、指标与固定账号偏好，未启用的模块及其指标自动隐藏，收起态使用首个已选且启用的指标；重新启用后恢复保存的选择并沿用原有服务刷新，等待首个采样或硬件不支持时显示“—”，不会填入模拟数值。关闭 AI 用量或取消来源时隐藏相应额度并取消旧配置的在途刷新；快速重新启用也不会接收旧请求的返回值。关闭休息功能后停止计时显示更新与操作。电池基础信息独立于能耗开关，关闭能耗不影响基础电量与电源短提示；取消灵动岛的电池场景才移除它新增的基础电量需求和系统事件监听，不影响其他界面的读取方。
- AI 场景复用当前配置的 `AIUsageController`、Magpie 或本机来源及原有刷新周期。默认优先取首个有当前新鲜额度的账号（其次为可展示的旧值），也可以固定主显示账号；账号消失时明确提示不可用，不把另一账号的额度冒充原账号。仅在所选账号内比较有效额度窗口，收起态显示服务名、额度圆环及最紧张窗口的剩余／已用百分比，悬停补充账号、周期和重置时间，不被今日 Token 替代；展开后显示该账号的各窗口、重置时间、上次读取时间及可选的今日 Token。过期窗口不代表当前额度，旧值带有时钟标记及明确提示；缺失或无限额度不当成零。仅为所选账号的下一个重置时间安排一次性失效，及时移除过期摘要并重新判断自动关注；不发起网络请求或扫描。内置 Codex、Claude 的已知周期可在额度条上显示时间进度刻线，跟随剩余／已用方向及 RTL 布局；陈旧值、无限额度、周期外或缺少可靠周期长度时不显示刻线，不根据 Magpie 名称猜测。仅展开且存在有效刻线时复用失效任务每分钟更新位置，收起或隐藏后不保留这项刷新。
- 电池场景显示基础电量、电源状态、系统提供的剩余／充满时间及健康度。不为该场景开启温度、功耗、App 能耗或历史采集；无其他需求时基础电量每 10 秒读取一次。无电池或读取失败时显示数据不可用，不伪造满电或续航；接通电源但未充电时不显示充满估计。底部入口打开现有电池页面。勾选电池场景且灵动岛可见时，沿用基础电量采样并注册系统电源事件，接通／断开、未接电时首次降至 20% 及充满时在收起态提示约 4 秒；首次读取或恢复显示不补播。提示不改变偏好或当前场景，进入预览／展开会清除，阅读期间的事件不会延迟弹出。隐藏或关闭时取消提示、事件读取及系统监听。
- 确认没有内置电池时，隐藏电池场景、场景设置与默认场景选项，不为灵动岛请求电量采样或注册电源事件。保存的电池偏好保留，当前场景临时回退到首个可用场景；所有已选内容都不可用时释放灵动岛窗口及展示需求，保留设置和菜单栏入口；重新可用后从收起态恢复。读取失败或尚未确认时保留入口，避免将暂时不可读误判为无电池。其他窗口的基础电池需求及能耗监控保持独立。
- 展示层级统一为收起摘要、悬停预览的上下文、点击展开的详情与操作。默认固定场景；可开启“自动关注”，仅在收起时优先展示未接电且不高于 10% 的电量，其次是所选账号的新鲜有效额度耗尽。过期或陈旧额度不触发切换，展开后保持正在阅读的页面。关闭、锁屏、休眠和全屏隐藏均释放展示需求。
- 休息场景复用 `RestController` 的当前阶段、剩余时间与开始／暂停／继续操作，与主窗口和迷你 HUD 同步。仅当前场景可见时加入原有倒计时显示需求；没有独立计时器。
- 点击收起的岛立即展开，默认悬停 250 ms 显示简略预览；离开简略预览时收起。悬停展开可设置等待时间和移开后的收起延迟，重新移入会取消待执行的收起。明确点击展开后移开指针仍保持展开，点击外部或按 Esc 收起。悬停不抢键盘焦点、不监听其他应用的键盘。
- 收起态高度为 32 点，宽度按当前读数在 120–260 点之间调整，仅保留场景图标、读数与展开提示。展开可选紧凑（360 × 300 点）、标准（420 × 320 点）或自定义（宽 360–600 点、高 300–480 点），并按可用屏幕空间约束。默认使用“悬浮胶囊”，所有状态均位于菜单栏下方，间距可选 8–32 点；菜单栏自动隐藏时去掉菜单栏占位，只保留设定间距和目标屏幕的刘海安全区。选择“顶部贴合”后，外形连接屏幕顶边，使用内凹肩部和圆角底边，展开方向保持向下；读数与按钮仍在菜单栏及刘海下方，顶部连接区域不放内容。贴合模式隐藏间距设置，保留原有间距供切回悬浮时使用；收起宽度额外计入肩部及摄像头宽度，展开尺寸包含两侧肩部，连接区高度另计。刘海屏幕以摄像头空隙居中。两种模式均低于系统菜单与状态栏层级，菜单栏可覆盖顶部连接区域；不申请辅助功能权限、不检测菜单位置、不增加轮询。
- 显示器列表标明内置／外接屏幕。默认优先选择当前连接的内置屏幕，无内置屏幕（包括合盖外接）时使用系统主屏幕，不跟随前台窗口所在屏幕。手动选择的显示器以稳定 UUID 保存在本机，断开时临时回退，重新连接后恢复选择。设置备份保存展示偏好，恢复时保留本机的显示器选择。
- 默认全屏时隐藏。桌面、前台应用或屏幕变化时，通过公开窗口边界判断所选屏幕是否被前台应用完全覆盖，不读取窗口标题、不申请辅助功能权限，也不增加定时轮询；无边框覆盖整屏的窗口也按全屏处理。此识别仍需覆盖不同应用与多显示器组合。
- 屏幕配置变化后重新定位；桌面与前台应用切换经事件防抖后也校正位置，即使全屏判断未变化仍将可见窗口重新锚定顶边，不增加轮询；全屏隐藏、锁屏、显示器休眠、系统休眠时释放窗口内容及其展示需求，恢复后从收起状态开始。关闭时移除观察者与输入监听，其他窗口和历史记录所需的原有采集继续按其需求运行。
- 窗口形状沿用设计令牌的 180 ms 短过渡，同步裁剪内容，中途可反向操作；键盘操作与系统开启“减少动态效果”时即时变化，读数不做装饰动画。

贴合模式的连接区按实际菜单栏占用和刘海安全区留白：无刘海且菜单栏自动隐藏时，收起总高度为 32 点，不另加菜单栏高度；临时呼出系统菜单时，系统界面优先覆盖岛。悬浮模式只保留菜单栏实际占位及设定间距，不为已隐藏的菜单栏预留固定高度。两种模式都使用目标屏幕的安全区，不按内置／外接类型猜测是否有刘海；短暂呼出菜单不触发位置动画，系统菜单优先覆盖。

本阶段使用原创实现，不包含 vorssaint-utils 的源代码或素材。真实多显示器、刘海屏、全屏应用与 Mission Control 的组合仍需在对应硬件上验证。
